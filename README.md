# Замер скорости скачивания

Автор: [@devrhab](https://t.me/devrhab).

Скрипт принимает URL, скачивает ресурс **10 раз** и выводит среднее время запроса,
общий объём данных и скорость в **МБ/с** и **Мбит/с**. По умолчанию запросы идут
последовательно; флаг `--parallel` запускает десять запросов параллельно.
В терминале видна таблица всех попыток с цветными статусами, прогрессом,
спиннером и скоростью каждой загрузки в **МБ/с**.
Файл читается частями до 64 КиБ, не сохраняется на диск и не хранится целиком в памяти.

## Установка

Требуется Python **3.11+**. Из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Команда установки также обновляет существующее окружение: она добавит `rich`,
который отвечает за оформление и анимацию интерфейса.

В Windows используйте `py -3 -m venv .venv`, затем в PowerShell
`.venv\Scripts\Activate.ps1`.

## Запуск

Передайте прямую HTTP- или HTTPS-ссылку на файл. Готовые примеры PNG:

| Пример | Размер | Ссылка |
| --- | --- | --- |
| Небольшая картинка | 271 068 байт, около 270 КБ | [sample-hut-400x300.png](https://samplelib.com/png/sample-hut-400x300.png) |
| Большая картинка | 4 201 559 байт, около 4.2 МБ | [sample-photo-1920x1080.png](https://samplelib.com/png/sample-photo-1920x1080.png) |

Последовательно, небольшой файл:

```bash
python speed_test.py "https://samplelib.com/png/sample-hut-400x300.png"
```

Последовательно, большой файл:

```bash
python speed_test.py "https://samplelib.com/png/sample-photo-1920x1080.png"
```

Десять загрузок большого файла одновременно:

```bash
python speed_test.py "https://samplelib.com/png/sample-photo-1920x1080.png" --parallel
```

Дополнительные параметры можно сочетать:

```bash
python speed_test.py "https://samplelib.com/png/sample-hut-400x300.png" --parallel --plain --timeout 60
python speed_test.py --help
```

Можно передать свой URL. Кавычки нужны, в частности, если он содержит `&`.
Скачивается любой тип файла, расширение не проверяется. В обоих режимах выполняется
десять скачиваний: потребуется примерно десятикратный размер файла в трафике.

`--timeout` по умолчанию равен 30 секундам и должен быть положительным конечным
числом. Он ограничивает ожидание соединения и периоды отсутствия входящих данных,
а не общее время скачивания: пока данные поступают, загрузка может идти дольше.
Слишком большие значения, превышающие предел платформы, отклоняются до запроса;
допустимый максимум указан в `--help`.

## Интерфейс

В обычном терминале таблица обновляется на месте 10 раз в секунду. Все десять
попыток видны сразу. С `--parallel` несколько строк активны одновременно,
а без флага активна одна. Пример последовательного режима во время загрузки:

```text
Замер скорости скачивания
Последовательно · Завершено: 1/10
╭────┬───────────────────┬──────────────────┬──────────────┬─────────┬─────────╮
│  № │ Статус            │         Прогресс │        Объём │   Время │    МБ/с │
├────┼───────────────────┼──────────────────┼──────────────┼─────────┼─────────┤
│  1 │ ✓ Готово          │ ━━━━━━━━━━━ 100% │ 5.0 / 5.0 МБ │  0.50 с │  10.000 │
│  2 │ ⠋ Загрузка        │ ━━━━         40% │ 3.2 / 8.0 МБ │  0.32 с │  10.000 │
│  3 │ · Ожидание        │                — │            — │       — │       — │
│  4 │ · Ожидание        │                — │            — │       — │       — │
│  5 │ · Ожидание        │                — │            — │       — │       — │
│  6 │ · Ожидание        │                — │            — │       — │       — │
│  7 │ · Ожидание        │                — │            — │       — │       — │
│  8 │ · Ожидание        │                — │            — │       — │       — │
│  9 │ · Ожидание        │                — │            — │       — │       — │
│ 10 │ · Ожидание        │                — │            — │       — │       — │
╰────┴───────────────────┴──────────────────┴──────────────┴─────────┴─────────╯
```

- **Ожидание** — попытка ещё не началась; строка серая.
- **Ожидание ответа / Загрузка** — текущая попытка; голубая строка со спиннером.
  Анимация продолжается и во время пауз сети.
- **Готово** — файл полностью прочитан; строка зелёная, объём и время сохранены.
- **Ошибка / Прервано** — красная или жёлтая строка; оставшиеся попытки получают
  статус **Не запускалась**.

Колонка **МБ/с** показывает среднюю скорость каждой попытки с момента её начала:
полученные байты / прошедшее время / 1 000 000. Во время загрузки значение
обновляется, после завершения фиксируется. Это скорость отдельного запроса;
общая скорость всех параллельных загрузок появляется в итоговом блоке.

Проценты появляются, только если известен размер файла. Без `Content-Length`
и при chunked-передаче видны спиннер, скачанный объём и время без процентов.
Объём обновляется по мере поступления данных: чтение не ждёт заполнения блока
в 64 КиБ. Единицы десятичные:
Б, КБ, МБ или ГБ в зависимости от размера. В окне уже 80 символов полоса
заменяется процентом. После успеха таблица остаётся в консоли, а под ней появляется
отдельный блок «Результат» со скоростью, средним временем и суммарным объёмом.

`--plain` включает текстовый вывод без анимации и цветов; скорость каждой попытки
печатается в её итоговой строке. При параллельной загрузке эти строки появляются
по мере завершения запросов и могут идти не по порядку номеров. Этот режим
также включается автоматически при перенаправлении stdout в файл или канал
и при `TERM=dumb`. Для таблицы запускайте команду в терминале, без `|` или `>`.

Условный пример с `--plain` для десяти скачиваний по 5 МБ за 0,5 секунды каждое
(промежуточные строки сокращены):

```text
Запрос 1/10: 0.500 с, 5000000 байт, 10.000 МБ/с
Запрос 2/10: 0.500 с, 5000000 байт, 10.000 МБ/с
...
Запрос 10/10: 0.500 с, 5000000 байт, 10.000 МБ/с

Среднее время запроса: 0.500 с
Скачано: 50000000 байт (50.000 МБ)
Скорость: 10.000 МБ/с (80.000 Мбит/с)

Автор: @devrhab — https://t.me/devrhab
```

## Как считается результат

Каждый замер начинается непосредственно перед GET-запросом и заканчивается после
полного чтения тела ответа. Используется монотонный таймер `time.perf_counter()`.
Время включает установку соединения, если она нужна, ожидание ответа, переходы по
редиректам и получение тела; печать результата в него не входит.
При подключённом отображении callback передаёт прогресс. В живом режиме он лишь
обновляет состояние, а отрисовку выполняет фоновый поток Rich; в текстовом режиме
промежуточные уведомления игнорируются. Небольшие расходы на callback входят в замер;
финальная отрисовка выполняется после фиксации времени.

- Среднее время запроса: `сумма времени всех запросов / 10`.
- Объём: сумма реально прочитанных байтов тел конечных ответов.
- Последовательная скорость, МБ/с: `общий объём / сумму времён запросов / 1_000_000`.
- Параллельная скорость, МБ/с: `общий объём / длительность запуска группы / 1_000_000`.
- Скорость, Мбит/с: `скорость в МБ/с × 8`.

МБ — десятичные мегабайты (1 000 000 байт), Мбит — десятичные мегабиты.
Для параллельного режима длительность — время от начала запуска группы до
завершения последней загрузки. Времена перекрывающихся запросов не складываются
при расчёте общей скорости. Например, если десять файлов по 1 МБ скачаны за
2 секунды, общая скорость равна 5 МБ/с. Среднее время отдельного запроса
в обоих режимах считается как сумма его длительностей / 10.
Скорость не усредняется по скоростям отдельных запросов. Значения округляются
только при выводе; в узкой колонке большие скорости показываются с меньшей точностью.
Длительное время в таблице также округляется до помещающейся точности;
при необходимости секунды заменяются минутами, часами или днями. Единица остаётся видна.

Скрипт отправляет `Accept-Encoding: identity` и читает `response.raw` без
декомпрессии. Даже если сервер вернёт сжатое тело, будет учтён его переданный,
а не распакованный размер. HTTP-заголовки, обрамление chunked-передачи и накладные
расходы TCP/TLS не учитываются. Заголовок `Content-Length` не используется
для подсчёта объёма; файл можно скачать и без него.
В интерфейсе корректный положительный `Content-Length` используется только
для отображения прогресса; при chunked-передаче он игнорируется.

В последовательном режиме запросы выполняются через одну `requests.Session`,
соединение может переиспользоваться. В параллельном режиме используется
`ThreadPoolExecutor` с десятью рабочими потоками и отдельная сессия на каждый запрос.
Дополнительных прогревочных запросов и повторных попыток нет.
Редиректы обрабатываются автоматически: один из десяти замеров может включать
несколько HTTP-переходов. Проверка TLS-сертификатов включена.

Это скорость скачивания **с выбранного сервера**, а не гарантированная пропускная
способность интернет-канала. На результат влияют сервер, маршрут, задержка,
размер файла и другие загрузки. Маленький файл даёт менее показательный результат.
Скрипт не использует локальный кеш ответов; сервер или CDN может отдавать файл
из своего кеша, но его тело всё равно передаётся по сети при каждом скачивании.

Подробнее: [потоковое чтение в Requests](https://requests.readthedocs.io/en/latest/user/quickstart/#raw-response-content),
[таймауты](https://requests.readthedocs.io/en/latest/user/quickstart/#timeouts).

## Ошибки

При первой HTTP-ошибке, сетевой ошибке, таймауте, обнаруженном обрыве загрузки
или пустом теле замер останавливается. В stderr выводятся номер запроса и причина.
Результаты уже выполненных запросов остаются в консоли, но итоговая скорость
появляется только после **10 успешных скачиваний**.
При ошибке и Ctrl+C анимация останавливается, курсор восстанавливается,
а таблица сохраняет последний статус каждой попытки.
В параллельном режиме при первой обнаруженной ошибке отменяются ещё не запущенные
попытки и подаётся сигнал остановки активным. Ошибочная строка остаётся красной,
остановленные загрузки отмечаются «Прервано». Остановка рабочих потоков
кооперативная: между чтениями проверяется сигнал отмены. При чтении тела достаточно
следующей доступной порции данных, ждать заполнения блока в 64 КиБ не требуется.
Уже начатое ожидание ответа или данных может продолжаться до возврата сетевого
вызова либо таймаута. То же правило действует при Ctrl+C, поэтому завершение
программы может потребовать ожидания. Итоговой скорости при прерывании нет.

Обрыв определяется по ошибке соединения, незавершённой chunked-передаче или
несовпадению с заявленным `Content-Length`. Если сервер обозначает конец тела
только закрытием соединения, отличить штатное закрытие от усечения без ошибки
на уровне протокола невозможно.

Коды завершения: `0` — успех, `1` — ошибка замера, `2` — некорректные аргументы,
`130` — остановка через Ctrl+C. Ожидаемые ошибки выводятся без traceback.

## Архитектура

| Module | Ответственность |
| --- | --- |
| `speed_test.py` | Разбор аргументов, создание отображения, вызов замера и коды завершения. |
| `measurement.py` | HTTP-загрузки, измерения, статистика и единый жизненный цикл последовательного и параллельного замера. Не зависит от Rich. |
| `console_ui.py` | Adapter уведомлений `RunObserver`: состояния строк, анимация и текстовый вывод в выбранный поток. |
| `tests/support.py` | Общий локальный HTTP-сервер и вспомогательные функции тестов. |

Interface `run_measurement(url, timeout, *, parallel=False, observer=None)` возвращает
статистику после десяти успехов. Замер сам закрывает сессии, останавливает потоки
и уведомляет об ошибке или отмене. Контекстный менеджер отображения отвечает
только за запуск и остановку анимации.

Для запуска без консольного вывода можно использовать:

```python
from measurement import run_measurement

stats = run_measurement("https://samplelib.com/png/sample-hut-400x300.png", 30)
print(stats.megabytes_per_second)
```

Термины, правила расчёта и контракт уведомлений описаны в [CONTEXT.md](CONTEXT.md).

## Тесты

После установки зависимостей:

```bash
python -m unittest discover -s tests -v
```

Отдельный набор также можно запустить из корня проекта:

```bash
python -m unittest tests.test_runners tests.test_terminal -v
```

Тесты используют стандартную библиотеку `unittest` и локальный HTTP-сервер
на свободном порту. Внешний интернет не требуется. Проверяются последовательность
и количество скачиваний, чтение полного тела, формулы, сжатые и chunked-ответы,
редиректы, таймауты, обрывы и валидация аргументов.
Включены сочетание gzip с chunked-передачей, циклический редирект и редирект
на HTTP-ошибку. Проверяются освобождение ответа при успехе, ошибке и отмене,
отмена до первого запроса и загрузка, которая длится дольше таймаута благодаря
непрерывному поступлению данных.
Дополнительно проверяются обновления прогресса, статусы таблицы и текстовый режим.
Поздние уведомления от потоков не должны менять уже завершённые или отменённые
строки; во время паузы сети средняя скорость в активной строке уменьшается.
Регрессионные тесты покрывают передачу порциями меньше 64 КиБ, отмену до получения
остатка тела, слишком большой таймаут и отображение длительных запросов.
Для параллельного режима сервер дожидается всех десяти запросов до отправки первого
ответа; тесты проверяют перекрытие загрузок, общий объём, формулу скорости и отмену
при ошибке, пустом теле, обрыве и таймауте.
В `tests/test_runners.py` управляемые часы проверяют, что печать результатов
не входит в измеренную длительность, а параллельные времена не складываются.
Эти проверки не зависят от скорости сети или компьютера.
Также проверяются запуск замера без консоли и единый порядок уведомлений
об ошибке и отмене в обоих режимах. Общие фикстуры находятся в `tests/support.py`.
На macOS и Linux тесты используют псевдотерминалы шириной 60, 80 и 120 символов:
проверяют движение спиннера при задержках сети, остановку по SIGINT (Ctrl+C)
и восстановление курсора. В Windows только эти PTY-тесты пропускаются.

## Публикация на GitHub

Создайте в своём аккаунте пустой публичный репозиторий `speed-test`, без
автоматического добавления README, лицензии или `.gitignore`. Затем из папки проекта:

```bash
git init -b main
git add speed_test.py measurement.py console_ui.py requirements.txt README.md CONTEXT.md .gitignore tests/ docs/
git commit -m "Add download speed measurement script"
git remote add origin https://github.com/YOUR_USERNAME/speed-test.git
git push -u origin main
```

Замените `YOUR_USERNAME` своим именем пользователя. Для отправки потребуется
настроенная авторизация GitHub. Проверяющему можно отправить ссылку на репозиторий:
все команды установки, запуска и проверки находятся в этом README.
