# Предметная область

| Термин | Значение и правило |
| --- | --- |
| Замер | Запуск десяти попыток для одного URL. По умолчанию последовательный; `--parallel` запускает их одновременно. Итог появляется только после десяти успехов. |
| Попытка | Один GET с разрешёнными редиректами и полным чтением конечного тела. Повторов после ошибки нет. |
| Измерение (`Measurement`) | Реально прочитанные байты тела до декомпрессии и длительность попытки от начала запроса до конца чтения. Заголовки и транспортное обрамление не считаются. |
| Статистика (`Statistics`) | Общий объём, средняя длительность попытки, скорости в МБ/с и Мбит/с. МБ содержит 1 000 000 байт. |
| Длительность замера | Для последовательного режима — сумма длительностей попыток. Для параллельного — время от запуска группы до последней завершённой загрузки. Печать результатов не добавляется к длительности. |
| Отображение | Необязательный получатель уведомлений замера. Показывает прогресс и результат, но не управляет загрузками или их отменой. |
| Отмена | Кооперативная остановка при ошибке или Ctrl+C. Уже заблокированный сетевой вызов должен вернуть данные или ошибку; таймаут ограничивает простой, а не общую длительность. |

# Архитектурные соглашения

- **Module замера** — `measurement.py`. Его **Interface** `run_measurement()`
  скрывает владение сессиями, потоками, временем и отменой. Низкоуровневые
  `download()` и `calculate_statistics()` также доступны для отдельных измерений.
- **Seam уведомлений** — `RunObserver`. **Adapter** `RunDisplay` отображает
  результат в консоли; тестовый Adapter записывает уведомления без Rich.
  При `observer=None` замер вообще не использует консоль.
- `start_attempt` и `update` могут выполняться из рабочих потоков: Adapter
  синхронизирует состояние, а отрисовку выполняет отдельно. `finish_attempt`,
  `fail_attempt` и `abort` вызываются в потоке, запустившем замер.
- При ошибке загрузки замер уведомляет `fail_attempt`, затем `abort`; при Ctrl+C —
  только `abort`. Уведомление об отмене происходит до ожидания завершения потоков.
  Поздние обновления не должны возвращать завершённую строку в активное состояние.
- **Module CLI** — `speed_test.py`: аргументы, выбор отображения, сообщения в
  stderr и коды завершения. Зависимости направлены к Module замера;
  `measurement.py` не импортирует CLI или Rich.
- **Locality**: правила выполнения принадлежат замеру; формат и состояния строк —
  отображению. **Leverage**: один Interface выполнения используется CLI и тестами
  в обоих режимах без дополнительной координации завершения со стороны caller.
